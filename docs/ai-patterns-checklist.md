# AI 패턴·가독성 체크리스트 (한국어 콘텐츠용)

문장 단위로 대조한다. 각 항목은 [문제 → 고치는 방향] 구조.
항목 안의 예시 문장은 방향을 보여주는 것일 뿐이니 그대로 옮겨 쓰지 말고, 검토 중인 글의 맥락에서 새로 만든다.

## A. AI 특유의 패턴

1. **뻔한 서론/결론** — "오늘은 ~에 대해 알아보겠습니다", "결론적으로", "종합하면", "지금까지 ~를 살펴보았습니다" → 삭제하고 구체적 사실·숫자·질문으로 시작/마무리.
2. **상투적 강조 표현** — "매우 중요합니다", "주목할 필요가 있습니다", "핵심 포인트는", "게임 체인저", "~라고 해도 과언이 아니다" → 왜 중요한지 구체 내용으로 대체.
3. **과잉 균형 양비론** — "장점도 있지만 단점도 있습니다", "긍정적 측면과 부정적 측면이 공존" → 글쓴이의 무게중심이 드러나게. 판단이 어려우면 판단이 어려운 이유를 쓴다.
4. **"단순한 X를 넘어" 대조 구문** — "단순한 유행을 넘어 하나의 문화로", "A가 아니라 B다", "A에 그치지 않고 B까지" 반복 → 대조 틀을 버리고 B의 내용만 직접 서술. 대조가 꼭 필요하면 한 편에 1회만.
5. **삼항 나열 습관** — "속도, 비용, 안정성 모두", "빠르고 간편하며 안전한"처럼 형용사·명사를 3개씩 묶는 버릇 → 논지에 필요한 하나만 남기고, 남긴 것을 구체 사례나 숫자로 뒷받침.
6. **수사 의문문 남발** — "그렇다면 이게 왜 중요할까?", "~란 무엇일까요?"를 문단 도입·소제목마다 사용 → 한 편에 최대 1회, 나머지는 질문 없이 답부터. "X란 ~를 말한다"식 정의 시작 문단도 같은 부류.
7. **지시어 남발** — "이러한 상황에서", "이처럼", "해당 기업은", "이와 같은" 반복 → 지시 대상 명사를 직접 다시 쓰거나("이러한 상황에서"→"금리가 묶인 상태에서") 삭제.
8. **헤지(유보) 중첩** — "~일 수 있을 것으로 보인다", "~할 가능성도 배제할 수 없다" 연속 → 유보는 한 번만, 무엇이 확인되면 판단이 갈리는지 조건을 명시. 조건을 못 쓰면 문장 삭제.
9. **요약 반복** — 한 말을 문단 끝마다 다시 요약 → 한 번만 말하고 넘어간다.
10. **불릿·헤더 남발** — 3~4문장이면 될 내용을 불릿 6개로 쪼갬, 문단마다 소제목 → 이어지는 문단으로 합친다. 불릿은 진짜 목록(종목 리스트, 일정 등)에만.
11. **기계적 넘버링** — "첫째, 둘째, 셋째" 나열 → 흐름으로 연결 ("먼저 ~. 여기에 ~까지 겹쳤다").
12. **두루뭉술한 일반론** — "많은 전문가들은", "일반적으로", "다양한 요인이" → 누가, 얼마나, 어떤 요인인지 특정. 특정 못 하면 문장 삭제.
13. **감탄·호들갑 과잉** — "놀랍게도", "무려", "충격적인" 남발 → 숫자가 크면 숫자가 말하게 둔다. 한 편에 최대 1회.
14. **완벽한 문어체 일관** — 처음부터 끝까지 흐트러짐 없는 설명문 → 짧은 구어 문장을 중간중간 섞어 호흡을 튼다 (예시를 복붙하지 말고 글 맥락에서 새로 만들 것).
15. **볼드·이모지 남발** — 문단마다 볼드, 이모지 장식 → 볼드는 1,000자당 1~2곳, 이모지는 X 포스트에서만 선택적으로.

## B. 번역투·어색한 한국어

16. **수동태 남발** — "~로 여겨진다", "~되어지고 있다"가 2회 이상 연속 → 능동태로 ("시장은 ~로 본다", "~라고 밝혔다"). "~로 알려져 있다"는 출처 불특정 전언에서 단독 사용은 자연스러우므로 연속일 때만 교정.
17. **영어 직역 어순** — "~에 있어서", "~함에 따라", "~에 의해", "~를 통해", "~에 대한/대해" 남발 → 조사로 단순화 ("~에서", "~하면서", "~가", "~로", "~를/은").
18. **명사화 문체** — "상승세의 지속 가능성에 대한 우려가 제기되고 있다" → 동사 중심으로 ("이 상승세가 계속될지 걱정하는 목소리가 나온다").
19. **줄표·부호 번역투** — 문장 중간의 줄표(—), 세미콜론(;), "A/B" 병기 남발 → 쉼표로 바꾸거나 문장 분리. 작은따옴표 강조('진짜' 문제는)도 한 편에 1~2회로 제한.
20. **어색한 단어 선택** — 사전적으로 맞지만 그 문맥에서 한국인이 안 쓰는 단어 (주가가 "증가했다"→"올랐다", "구매했다"→"샀다/매수했다", "언급했다" 남발→"말했다/밝혔다") → 해당 분야 실사용 언어로. 주식 글이면 개미·주도주·수급 같은 실사용 용어가 자연스러운 자리인지 확인.
21. **높임·문체 불일치** — 한 글 안에서 ~습니다/~다/~요 혼재 (의도된 전환 제외) → 채널 톤에 맞게 통일. 블로그는 ~다체 또는 ~요체 중 하나, X는 ~다체/명사형 종결.

## C. 가독성·리듬

22. **문장 길이 단조로움** — 비슷한 길이 문장 연속 → 긴 문장 뒤에 짧은 문장. 리듬을 만든다.
23. **문단 길이 단조로움** — 모든 문단이 같은 문장 수로 균등 분할 → 한 문장짜리 문단을 강조 지점에 1~2개 섞고, 핵심 문단은 길게 끌고 간다.
24. **같은 어미 반복** — 동일 형태("~했다", "~였다", "~습니다" 등 각각을 별개로 계산)가 3연속 이상 → 어미 교체·도치·명사형 종결을 섞되, 도치·명사형은 한 편에 2~3회 이내.
25. **한 문장 과적** — 공백 포함 100자 초과는 필수 분리, 쉼표 3개 이상(고유명사·항목 나열은 제외)은 권장 분리. 한 문장 한 정보, 80자 이내 권장.
26. **문단 과적** — 한 문단 5문장 초과 또는 공백 포함 약 200자(모바일 3~4줄) 초과 → 쪼갠다.
27. **접속사 과잉** — "그리고", "또한", "하지만"으로 시작하는 문장 연속 → 접속사 없이 이어지는지 먼저 시험, 안 되면 다양화.
28. **소리 내어 읽기 테스트** — 낭독했을 때 숨이 차거나 혀에 걸리는 문장 → 무조건 다시 쓴다. 최종 판정 기준.
29. **훅 검증** — 첫 3문장 안에 읽을 이유(구체적 사실, 숫자, 반전, 질문)가 있는지 검증. 1회차에서 이미 도입부를 교체했으면 재작성하지 말고 검증만, 훅이 없을 때만 재작성.
30. **채널 톤** — 블로그는 읽는 맛이 있는 서술형, X는 짧고 단정적인 훅. 두 채널 글이 같은 말투면 실패.

## 적용 예외 (모든 항목 공통)

- 공백 포함 약 500자 미만 단문(X 포스트 등)에는 문단 기준(23·26)과 훅 3문장 기준(29)을 적용하지 않는다. 단문의 훅은 첫 문장 기준으로 판정한다.
- 직접 인용(" ") 내부 텍스트와 [내 코멘트] 슬롯은 수정·카운트 대상에서 제외한다.
