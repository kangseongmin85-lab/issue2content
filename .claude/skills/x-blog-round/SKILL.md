# x-blog-round — 콘텐츠 1회차

이 스킬은 issue2content 저장소 루트에서 실행한다. 한 회차 = 이슈 1건.
글은 API가 아니라 **이 세션의 Claude가 직접 쓴다** (품질 책임도 이 세션에 있다).

## 0. 준비

- `전략.md`를 읽는다 (선정 기준·안전 규칙·알고리즘 반영 사항이 전부 여기 있다)
- 오늘 첫 회차라면(= out/오늘날짜/ 폴더가 없다면) 마지막 단계 9도 수행한다

## 1. 수집

```bash
python local_prep.py
```

`work/candidates.json`을 읽는다. 후보가 0건이면 "이번 회차 새 이슈 없음"을 한 줄
보고하고 회차를 종료한다 (억지로 만들지 않는다 — 루프에서는 noop 처리).

수집은 **최근 8시간**만 본다(부족하면 24시간으로 자동 확장). 각 후보에는
`newest_age_h`(가장 최근 기사가 몇 시간 전인지)와 기사별 `age_h`가 들어 있다.

## 2. 이슈 선정

**신선도가 화제성보다 우선한다.** 지난 이슈를 뒤늦게 쓰면 의미가 없다.

- `newest_age_h > 6` 인 후보는 **선정 금지**. 화제도가 아무리 높아도 지난 이슈다
- 6시간 이내 후보가 하나도 없으면 회차를 종료한다 (억지로 옛날 것을 쓰지 않는다)
- 2시간 이내 후보가 있으면 그중에서 고른다. 화제도 비교는 그다음
- 예외: 6시간이 지났어도 **지금 새 국면이 열린** 경우(후속 발표·정정·시장 반응
  본격화 등 최신 기사가 새 사실을 담고 있을 때)는 가능. 단 3단계에서 그 새 사실을
  원문으로 확인했을 때만이고, 글의 각도는 '어제 있었던 일'이 아니라 '지금 벌어진
  변화'여야 한다

그다음 전략.md의 '이슈 선정 우선순위'를 따른다: 화제성(score), 동점이면
AI×증시 > 연예 대형 기록 > 재테크 정책 > 스포츠 빅매치. 정치 공방·사건사고·범죄·
사망·사생활·루머 키워드는 **선정 금지** (후보에서 그것뿐이면 회차 종료).

## 3. 원문 확인 (사실 확보)

선정 이슈의 대표 기사 2~3건을 WebFetch로 읽는다. 구글 뉴스 링크는 리다이렉트를
반환하므로 안내된 URL로 한 번 더 호출한다. 목적:

- 카드와 본문에 쓸 **구체 수치** 확보 (제목만으로 쓰지 않는다)
- 기사 간 수치가 다르면 보수적인 쪽을 쓰고 출처를 남긴다
- 원문에서 확인 못 한 수치는 쓰지 않는다
- **신선도 재확인**: 원문이 실제로는 어제 사건의 재탕이면(새 사실 없이 요약·해설만)
  그 이슈를 버리고 다음 후보로 넘어간다. 후보가 없으면 회차 종료

## 4. 콘텐츠 작성 → work/draft.json

전략.md의 형식 규칙(수치 선두·질문 마무리·링크는 첫 답글·해시태그 0~1개)을
적용해 아래 스키마로 `work/draft.json`을 저장한다:

```json
{
 "keyword": "선정 키워드",
 "mode": "claude-code",
 "blog_title": "블로그 제목",
 "meta_description": "메타 설명 한 줄",
 "target_keyword": "SEO 키워드",
 "blog_body": "1500자 내외 마크다운. 소제목 2~3개, 하단 출처 목록, (금융이면) 투자유의 문구",
 "x_single": "280자 이내 본문. 첫 문장에 최강 수치, 끝은 질문. 외부 링크 금지",
 "x_reply": "첫 답글용: 블로그 링크 자리 [블로그 링크] + 보충 한 줄",
 "x_thread": ["큰 이슈일 때만 4~6개. 아니면 빈 배열"],
 "card_headline": {"kicker": "한 줄 맥락", "title": "핵심+숫자 12자 내외",
   "accent": "title 중 강조 부분", "sub": "부연 한 줄", "hook": "하단 훅 한 줄"},
 "card_stats": {"title": "수치 카드 제목",
   "stats": [{"label": "지표", "value": "수치", "note": "부연", "amber": true}],
   "source_line": "자료: ..."}
}
```

작성 품질 규칙 (린트를 따로 돌리지 않으니 처음부터 지킨다):

- AI 패턴 금지: 뻔한 서론/결론, "매우 중요"류 상투 강조, 양비론, 삼항 나열,
  수사 의문문 남발, 헤지 중첩, 첫째둘째셋째, "많은 전문가들", 번역투(~에 있어서,
  ~를 통해), 무려/놀랍게도 남발
- 동일 어미 3연속 금지, 100자 초과 문장 분리, 블로그는 서술형·X는 짧고 단정적
- 사실 창작 금지. 확인된 사실과 추정을 구분. card_stats 수치는 원문에서 확인된 것만

## 5. 카드 렌더

```bash
python render_local.py work/draft.json "out/날짜/시각_키워드"
```

예: `out/2026-08-19/1430_엔비디아`. PNG 경로가 출력된다.

## 6. (선택) AI 일러스트

score가 압도적(당일 최대급)이고 시각적 소재가 명확할 때만 recraft-image-gen
스킬로 1장 생성해 같은 out 폴더에 저장한다. 평시에는 건너뛴다 (크레딧 절약).

## 7. 발행

```bash
python publish_local.py work/draft.json "out/날짜/시각_키워드"
```

노션 저장 + 텔레그램 알림 + seen.json 기록까지 처리된다.
토큰 미설정 경고가 나오면 보고에 ".env 설정 필요"를 포함한다.

## 8. 채팅 보고 (회차의 최종 산출물)

다음 순서로 보고한다:

1. 선정 이슈와 선정 이유 한 줄, **최신 기사 몇 시간 전인지**, 확인한 핵심 수치
2. **X 본문** 복붙 블록 (코드블록)
3. **첫 답글** 복붙 블록 (블로그 링크 자리 포함)
4. 카드 이미지를 SendUserFile로 전송
5. 노션 URL, 골든타임 안내 (전략.md 시간대 기준)

## 9. (하루 첫 회차만) 전략 학습

WebSearch 1~2회로 X 알고리즘/성장 전략 최신 동향 또는 오늘의 한국 X 트렌드
특성을 확인하고, 새로 배운 것이 있으면 `전략.md` 학습 로그에 날짜와 함께 1~3줄
추가한다. 기존 전략과 모순되는 정보면 본문도 수정하고 로그에 사유를 남긴다.
