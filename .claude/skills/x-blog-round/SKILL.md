# x-blog-round — X 포스트 1회차

저장소 루트에서 실행한다. **한 회차 = 이슈 1건 = X 단독 포스트 1개.**
글은 API가 아니라 이 세션의 Claude가 직접 쓴다.

## 산출물은 X 포스트 하나뿐이다

만들지 않는 것: 블로그 글, 첫 답글, 스레드, 카드 이미지, 카드 렌더용 JSON,
업로드 전 체크리스트. 2026-08-20에 전부 잘라냈다 — 과했고, 정작 X 본문 품질이 뒤로 밀렸다.

## 0. 준비

`전략.md`를 읽는다 (선정 기준·안전 규칙·알고리즘 반영 사항이 여기 있다).

## 1. 수집

```bash
python local_prep.py
```

`work/candidates.json`을 읽는다. 후보가 0건이면 "이번 회차 새 이슈 없음"만 한 줄 보고하고
종료한다. 억지로 만들지 않는다.

수집은 최근 8시간만 본다(부족하면 24시간으로 자동 확장). 각 후보에 `newest_age_h`가 있다.

## 2. 이슈 선정

**신선도가 화제성보다 우선한다.**

- `newest_age_h > 6` 인 후보는 선정 금지. 6시간 이내가 하나도 없으면 회차 종료
- **지수·시장 전체 흐름 금지.** 코스피 등락, 사이드카, 환율은 증권사 앱만 켜도 보인다.
  개별 종목·기업·제품·임상 결과처럼 **특정 사건**이어야 한다. 후보 키워드가 '코스피'·
  '금리'·'특징주' 같은 카테고리 단위면 그 안의 단일 사건으로 좁히거나 버린다
- 후보의 기사들이 한 사건이 아니라 흩어진 주제면 선정하지 않는다 ("AI" 묶음에 무관한
  기사 8건 같은 경우 — 화제가 아니라 흔한 단어다)
- `seen.json`과 같은 사건이면 스킵한다
- 정치 공방·사건사고·범죄·사망·사생활·루머는 선정 금지

동점이면 전략.md의 우선순위를 따른다: AI×증시 > 연예 대형 기록 > 재테크 정책 > 스포츠.

## 3. 원문 확인 — 사실 + **의미**

WebFetch로 대표 기사 2~3건을 읽는다. 구글 뉴스 링크는 본문이 안 나오므로, WebSearch로
언론사 원문 URL을 찾아 다시 부른다.

**두 가지를 따로 확보한다.**

**(a) 사실** — 카드와 본문에 쓸 구체 수치. 기사 간 수치가 다르면 보수적인 쪽을 쓰고,
어느 쪽도 확신 없으면 **아예 쓰지 않는다**. 원문에서 확인 못 한 수치는 쓰지 않는다.

**(b) 의미 — 이게 왜 대단한가.** 이걸 별도로 **조사한다**. 수치만으로는 독자가 크기를
가늠하지 못한다. WebSearch를 한 번 더 써서 맥락을 찾는다:

- 사상 처음인가, 역대 최대인가, 몇 년 만인가
- 업계에서 이 사건이 무엇을 바꾸는가
- 전문가·기관이 뭐라고 평가했는가

이 조사 결과가 포스트의 2번째 블록이 된다. **자기가 지어내면 안 된다.** 근거를 못 찾으면
"대단하다"고 쓰지 말고 사실만 쓴다.

**신선도 재확인**: 원문이 어제 사건의 재탕이면 버리고 다음 후보로 넘어간다.

## 4. 포스트 작성 → work/draft.json

```json
{
 "keyword": "선정 키워드",
 "mode": "claude-code",
 "source_links": ["근거로 쓴 기사 링크 전부 — 다음 회차의 재탕 차단에 쓰인다"],
 "significance": "조사로 확보한 '왜 대단한가' 근거와 출처 (보고·노션용)",
 "x_single": "X 본문"
}
```

### 구조 (3단, 순서 고정)

```
1. 사실        — 무슨 일이 일어났는지. 가장 강한 수치를 첫 문장에
2. 의미        — 그게 어떤 의미이고 얼마나 대단한지. 3단계 (b)에서 조사한 근거로
3. 질문        — 하나만. 답이 갈리는 진짜 질문이라야 답글이 달린다
```

### 글자수 — X는 한글을 2로 센다

280 한도는 **한글 기준 실질 140자**다. 자수로 세면 반드시 초과한다. 작성 후 검증한다:

```python
def w(s):
    t = 0
    for ch in s:
        cp = ord(ch)
        t += 1 if (cp <= 4351 or 8192 <= cp <= 8205 or 8208 <= cp <= 8223
                   or 8242 <= cp <= 8247) else 2
    return t
```

여유 20~30을 남긴다. 후보를 3~4개 써서 측정하고 고르는 편이 빠르다.

### 문체

**글쓴이가 이 뉴스를 보고 생각한 흔적이 읽혀야 한다.** 수치를 나열하는 보도자료 톤은
실패다. 다만 근거 없는 감상·과장은 금지다 — 확인된 사실이 스스로 무게를 갖게 배치한다.

- AI 패턴 금지: 뻔한 서론/결론, 상투적 강조, 양비론, 삼항 나열, 헤지 중첩,
  "많은 전문가들", 번역투(~에 있어서, ~를 통해), 무려/놀랍게도
- 동일 어미 3연속 금지, 100자 초과 문장 분리, 짧고 단정적으로
- 외부 링크 금지(도달 50~90% 손실), 해시태그 0~1개
- 사실 창작 금지. 확인된 사실과 추정을 구분
- `docs/copyright-checklist.md`를 작성 원칙으로 선적용: 기사 문장 전재 금지(팩트만
  재서술), 한 출처 의존 금지(3개 이상 종합), 직접 인용은 출처 명시

## 5. 린트 2회

`docs/lint-protocol.md`를 참고하되 **2회로 실행**한다. 각 회차를 Agent 툴로 독립 실행한다 —
같은 컨텍스트에서 자기 글을 다시 보면 문제를 못 찾는다.

- **1회차 (교정)**: 원본 + `docs/ai-patterns-checklist.md` A·B·C절 통합 → 패턴·번역투·리듬 교정
- **2회차 (검수)**: 원본 + 1회차 결과 → 수치·구조(사실→의미→질문)·질문 마무리·가중 글자수
  복구 검증. **신규 수정 금지**, 복구와 최소 교정만

각 서브에이전트에 넘기는 것은 `x_single`뿐이다. 참고 사실은 "표현 판단용 배경"으로만 주고
본문에 다 넣지 말라고 명시한다.

**절대 금지**: 수치·출처 변경, 근거 없는 내용 추가, 질문 마무리 제거, 가중 글자수 초과.

2회차 결과로 `work/draft.json`을 갱신한다.

## 6. 발행

**노션** — `notion-create-pages`로 저장한다 (`NOTION_TOKEN`은 비어 있는 게 기본이라
`publish_local.py`의 노션 경로는 건너뛴다).

- parent: `.env`의 `NOTION_PARENT_PAGE_ID`
- 제목: `[YYYY-MM-DD] 키워드 — 한 줄 요약` (**형식 엄수** — 재탕 차단이 이 제목을 읽는다)
- 본문은 이 네 블록만. 그 이상 만들지 않는다:
  1. **X 발행용** — 포스트 본문 코드 블록 하나 (복사 버튼으로 통째 복사되도록)
  2. **왜 이 이슈인가** — 선정 이유 한 줄, 최신 기사 몇 시간 전, 골든타임
  3. **의미 근거** — 3단계 (b)에서 조사한 내용과 출처
  4. **출처** — `[매체명 - 제목](URL)` 형식. 수치가 엇갈려 쓰지 않은 것도 함께 적는다

**텔레그램 + seen.json** — 아래를 실행한다 (카드가 없으므로 이미지는 넘기지 않는다):

```bash
python publish_local.py work/draft.json out/날짜/시각_키워드
```

폴더가 없으면 만들어 둔다. 텔레그램 토큰이 없으면 그 단계만 조용히 건너뛴다.

## 7. 보고

1. 선정 이슈와 이유 한 줄, **최신 기사 몇 시간 전인지**
2. **X 본문** 복붙 블록 (코드블록) + 가중 글자수
3. 의미 근거 한두 줄과 출처
4. 노션 URL, 골든타임 안내 (전략.md 시간대 기준)
5. 린트 2회차 요약 한 줄
